# Forkarak native design

Mode: operate/read. A compact developer review surface, with a steel spork mark and a cool blue-gray palette. The existing conversation supplies the product brief and authorizes the build.

## Foundation
- Ground #20252c, sidebar #1b2026, raised surface #282f38, separator #343e49.
- Main ink #e5eaf0, secondary #a4b0be, accent #7fb8e2. Additions #83c4a1 on #234535; deletions #e5a0a5 on #492d35.
- UI type: IBM Plex Sans; code: JetBrains Mono. Korean falls back to the OS Korean sans. Body 13px, code 13px, panel title 12px, product 17px.
- Spacing 4/8/12/16/24; compact rows 28px, toolbar 36px, controls 28px. Controls radius 5px; main panes are flat and separated by a rule.
- Native keyboard conventions, visible focus, tooltips, drag-resizable panes. No dashboard cards or decorative metrics.

## First viewport
The 36px native titlebar keeps project tabs and the open-project action on the left, followed by Git actions. At compact widths, Stage / Commit remains visible and a native Git More menu retains secondary branch, stash, sync and operation commands. The titlebar stays on one row. Project tabs scroll horizontally when they overflow; the project picker exposes the complete list. Both the tabs and picker rows accept drag reordering, share their order, and persist it without switching the active project or reloading its reader. Hover reveals each action's name, and each icon has an accessibility label. The Graph/Code selector sits on the right, followed by the terminal, refresh and settings icons; compact widths use mode icons. Code View adds back and forward navigation immediately before the selector. The terminal button toggles a resizable bottom panel running an interactive login zsh for the selected worktree. Hiding the panel keeps the session alive.

Git Graph is the default working screen when there is no saved context; Settings can select Editor, and last-screen restoration is separate. A collapsible group for each of worktrees, local branches, remotes, tags and stashes sits to the left of the graph. Selecting a reference reveals its commit. Each commit table header has a draggable trailing edge. Header and rows scroll together horizontally when their widths exceed the viewport. The branch selector filters local and remote names and scopes the graph, search and pagination to the selected branch. Scrolling near the end loads the next 100 commits in that scope. Branch hover follows its first parent through merges. Cmd-F searches commit messages, authors and hashes across the repository. A commit context menu offers cherry-pick and revert. Local branch context menus name the source and destination for merge and rebase.

Selecting a commit opens its changed files and read-only diff below the graph. The file toolbar offers unified and synchronized side-by-side diff, History and Blame, with parent selection for merges. Selecting the working-changes row opens staging, a diff and a commit message in the same pane. Each worktree remembers its branch filter, column widths, side-by-side diff ratio, pane dimensions and collapsed sections.

Code View retains the existing changed files/all files, search and current-file reader, including per-worktree reading positions and language navigation. Settings adjusts interface and code font sizes independently and provides an application-wide zoom. Unified and side-by-side patches keep the language colors of Code View. Background tints and gutter signs identify additions and deletions in both themes. The two sides use their own paths and source snapshots so a rename or a multiline comment can change how the same text is colored. File/text search switches to Code View. Historical editors never invoke current-source language navigation. Project/worktree opens follow the selected default or restored screen and reject old asynchronous history results. Footer: worktree path and loading/analysis status. The worktree sidebar has no explanatory footer caption.

Graph reference badges use the available column width. A +N control opens the full reference list; each entry supports graph hover and branch context actions. Increasing the column width reveals more badges. A branch menu names the source and current destination before the existing merge confirmation.

Code View has one row of disambiguated file tabs followed by one responsive 36px reader command bar. Its density follows the reader's measured width: frequent view, review, Edit/Save, code-support and More controls stay on that row, while secondary commands remain available in native menus. Full paths are available in tab tooltips and the copy-path command. Working files open read-only by default until explicit Edit; Settings can choose direct editing independently of the default working screen. Save (Cmd-S) changes only the working file; Save + Commit in the menu opens staging after the save. Dirty indicators and retained drafts survive refresh, navigation and restart, and stale disk contents cannot be overwritten silently. “디스크와 비교…” opens original, retained draft and current disk panes with an editable result. Applying the result revalidates disk and changes only the draft; Save remains explicit. Rereading disk preserves the editable result. Historical previews remain read-only and use the same compact reader bar without working-file edit or analysis commands. The file tree has disclosure chevrons and whole-tree controls, with collapse state isolated by worktree. Search reveals matches independently of collapsed folders.

Selected controls and rows use cool blue fills in dark mode. Git dialog controls have raised backgrounds, visible borders, pointer cursors and distinct hover, pressed, focused and disabled states. Settings includes copyable Claude/Codex launch commands and a CLI guide. Agent commands return JSON, require explicit worktree scope, and require --yes for writes; private local GUI commands navigate without granting language-analysis trust.

## Signature behavior

The staging file lists support Cmd-click to toggle files and Shift-click to select a range. Explicit mark controls are keyboard accessible. Selected-file counts, clear selection and selected-only Stage/Unstage actions stay with their own staged/unstaged list. File marks are bound to the worktree and index snapshot; replacing that snapshot clears the marks. Diff line marks and the single-file preview remain independent.

Stash and Pop are separate icon buttons with hover names. Pop opens a bounded list of shared stash identities, each with preview and an explicit action. The confirmation names the selected stash and destination worktree. Detailed actions use “Apply · 보관 유지” and “Pop · 적용 후 제거”; a failed or conflicting apply retains the stash.

The existing footer offers a compact branch/upstream and locally known ahead/behind control; its detail names the selected worktree's last Fetch time and the local-reference scope. Network forms initialize from the current branch's actual upstream, including differently named remote branches. Selecting another Push source clears the old remote choice and resets the destination for explicit review. Confirmations bind the source commit and remote configuration; local changes during confirmation require reopening it. Optional upstream setup is visible before Push.

The branch creation form chooses HEAD, a full local/remote reference or an explicit full commit OID. Create-and-switch is optional; remote tracking has a separate checkbox. The source commit and current HEAD/branch remain visible in confirmation. Remote branch and commit context actions open this same form. Local branch rename has a separate guarded confirmation.

Git actions expose a worktree-scoped history of the latest 20 operations for the running app. Running actions show elapsed time without invented transfer progress. Completed actions preserve bounded stdout/stderr; failures retain raw diagnostics and offer specific explicit next actions. Ordinary inspection never invokes those actions.

Conflict review shows Ours and Theirs in simultaneous read-only panes, with an optional Base pane above the editable result. The scrollable body and fixed footer fit the minimum window. Previous/next opening-marker controls move the result caret; next-file navigation uses the current unresolved list. Navigation and closing retain editors under their exact worktree/file keys. Direct editing and side choices retain a reversible manual result. Explicit draft discard names the selected file and changes no disk/index content. Retained snapshots are not silently rebased onto external changes.

Graph and Code share the worktree/ref sidebar, including branch context actions. Code defaults to working files versus HEAD. The separate “브랜치 비교…” action accepts a base and shows its applied merge-base comparison; “HEAD로 돌아가기” restores the default. Failed comparison requests retain the previous baseline and reader. Comparison is isolated per worktree and independent of the graph filter. Sidebar and Code file-list visibility are stored per worktree. Persistent toolbar toggles and View menu actions restore hidden panes; Cmd-Option-B toggles the sidebar and Cmd-Shift-B toggles the Code files pane. Small windows use responsive icons and native overflow menus while titlebar and reader commands remain single rows. Pane widths are clamped for the available reading area without discarding the saved width choices.

File controls offer “검토 완료”, with checks and counts in changed-file lists. Verification is pending until the stored content stamp matches the actual file and comparison. Unsaved or stale drafts, binary and truncated previews cannot be marked. Diff controls offer whitespace-only display filtering and previous/next change navigation with Option-Up/Down. Changed words get a stronger tint within changed lines. Raw patches and index staging remain unchanged and unfiltered.

The terminal panel contains multiple tabs per worktree. Adding and selecting tabs never changes another worktree's terminals. Hiding retains every session; closing a tab terminates only its owned shell and foreground process group. Closing the last tab hides the panel. Exited tabs retain their status and offer restart. Update/restart checks include hidden and inactive live sessions.

Each worktree restores its exact reading context. The current comparison and worktree stay visible as the code reader moves through definitions and back. Filesystem notifications cover the worktree and real Git/common directories, including linked worktrees. A 600 ms quiet interval coalesces changes, with a bounded burst interval. A lightweight content/ref summary precedes selected-worktree reloads. Automatic refresh preserves selected files, code/diff positions and immutable historical selections; unsafe interaction states retain queued events. It avoids transient layout-changing notices and does not steal editor focus. Failed reads retain the previous view and allow retry on a later notification or manual refresh.

## Empty and multiple projects
Closing all projects restores the welcome screen with project-open action and recent-project list. Worktree sessions, search and reading positions remain isolated within each project. Project close never deletes a repository or worktree.

## In-app updates
The installed app checks for stable releases in the background. A compact banner on the welcome screen or workspace offers the download. Settings also shows the installed version and a manual check. Download and verification leave the window usable. Once ready, the user chooses when to restart. The app remembers the active worktree, reading view and commit drafts, and asks for confirmation if restarting would end a live terminal or discard conflict-editor input.

## Native verification
Inspect the actual macOS window at 1440×900 and a smaller window. Web-only detectors do not apply. Check open/empty/error/loading, long file paths, keyboard navigation, diff/code switch, worktree isolation, and external modifications.
