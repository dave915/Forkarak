# Stash and conflict workflow

`operations::workflow` adds inherent methods to `GitOperations`; existing basic-operation methods and types remain compatible. All explicit writes must use the application's single `run_git_job` guard. Inspection never starts an operation.

Stashes are shared by the entire repository, including linked worktrees. `stashes()` returns the commit OID, current reflog selector, Git's recorded subject and source-branch context. That branch is historical context, not ownership. Patch and file-content reads and apply use the OID. Drop revalidates selector, OID and subject immediately before `git stash drop`; stale selection fails. Pop applies by OID then revalidates before drop; conflicts, failed apply and failed drop retain the entry. If apply succeeds and drop fails the error explicitly reports the applied/retained state. Git can still be changed by another process between revalidation and a command; there is no cross-process workflow transaction. Refresh stale selections instead of retrying an index blindly.

`stash_save(message, include_untracked)` captures tracked changes and optionally nonignored untracked files, never ignored files. It temporarily clears literal-pathspec mode for this path-free command: Git internally uses a magic pathspec for untracked cleanup, and inheriting literal mode leaves the saved untracked files behind. No user pathspec is interpreted.

`conflicts()` reads index stages. `inspect_conflict()` captures base (1), ours (2), theirs (3), and the current disk version. Missing stages remain absent; choosing an absent side explicitly means deletion. Rebase labels explain that ours is the rebased-onto history and theirs is the replayed commit. Stash conflicts have no merge continuation; resolving them never drops their stash.

`resolve_conflict(snapshot, resolution)` accepts Ours, Theirs or edited UTF-8. It validates the worktree, exact stage modes/OIDs, disk bytes, inode, modification time and mode before saving. Directory-relative no-follow descriptors reject traversal, administration paths and symlink escapes, including parent symlinks. Saving uses a fresh inode and atomic rename, so hard links are not modified in place. A second pre-save check rejects edits during preparation. External programs do not participate in a transaction: an edit racing the final filesystem syscall or Git's later staging still cannot be locked out by this UI. Avoid simultaneous resolution in another editor. Staging failure leaves the saved result on disk and reports that partial state; reopen the conflict to inspect/retry. No commit or push is implicit.

Resolution is bounded to 128 KiB per file/stage. Binary sides can be chosen byte-for-byte but cannot be text-edited. Symlink, submodule and other unsupported modes and larger working files require an external Git tool. Ordinary file readers remain read-only; only the explicitly opened conflict result editor is writable.

`in_progress()` detects merge, rebase, cherry-pick and revert markers in the selected worktree, including sequencer operations. `finish_operation(expected, abort)` checks a fingerprint of operation metadata and HEAD before acting. Continue refuses unresolved stages, uses noninteractive editors, and respects the existing Git configuration and hooks. Abort is a separate explicit action whose UI confirmation names the operation and worktree and warns that resolution edits may be discarded. No automatic skip, force, reset or stash deletion is performed.

Temporary-repository tests cover tracked/untracked/ignored stash behavior, patch/content inspection, linked-worktree sharing, stale stash selections, apply/pop retention, stage contents, edited save and stage, stale disk/index protection, add/add and delete/modify, binary/size limits, traversal and symlinks, partial stage recovery, and continue/abort for merge/rebase/cherry-pick/revert. Fixture identity and configuration are isolated; tests use no real user repositories or remotes.
